# monastery 宪法

> 原则层,坐在架构之上。任何设计取舍以此裁决。
> (不叫 "thesis"——那是每个被管仓库的范围定义 `.monastery/thesis.md`,另一回事。)

## 一句话

**monastery 是一层薄的安全/治理外壳,把一个强大、不被信任、还在变强的 agent,安全地指向一个仓库。**

---

## 一、安全与有用解耦
外壳保证**安全**(永远成立);agent 提供**有用**(随模型涨)。
**agent 的强弱只改变 monastery 多自治,不改变它多安全。**

## 二、约束而非信任
外壳**不信任** agent,它**约束** agent。**越强的 agent 越需要约束,而不是越不需要。**

## 三、agent 只提议,外壳执行
agent **永不碰 git/gh**。它从**能力词表**里提议动作;外壳执行安全的、闸门拦截 risky 的。
**代码层面不存在让 agent 触发 risky 动作的路径。**

## 四、对外/不可逆动作必须人放行
merge、close、以 repo 名义正式回复——**没有人类信号(PR = Merge,issue = 👍)就不执行**。这是**强制**,不是默认。

## 五、GitHub 是唯一真相
状态、进度、待审都在 GitHub(label + marker)。本地只有**可丢缓存**,丢了从 GitHub 重建。

## 六、一切副作用幂等
动手前查 GitHub marker;崩溃重放**绝不重复**。每个动作的幂等键**从 GitHub 可观测**,不靠本地状态。

## 七、协议是三方共享的契约
状态 / 标签 / marker / 信号 / propose→approve→execute——**人、agent、外壳共用同一份 GitHub-可观测的语言**。外壳强制它,agent 被告知它,人遵循它。

## 八、不给模型推理搭脚手架
凡是更强模型会自己做的(分类、设计、对话判断),交给 agent,**别手搓 judge / dispatch / 富生命周期状态机**。

## 九、最薄即最耐用
外壳只拥有**模型不提供的东西**:状态(粗)/ 规则(不变量)/ 幂等 / 强制 gate / 人类协议 / 能力词表。**其余皆可换、可弃。**

## 十、可接受的失败是噪声,不是损害
差 agent 的最坏结果是**没用的提议 + 在闸门处被拦**;安全层兜底。我们容忍不够有用,不容忍不安全。

## 十一、覆盖是安全,强调是判断
外壳保证**每个 open item 每 tick 都被检视**(不饿死)——这是**活性,归安全**;agent 在"被检视的全部"里判断**先做什么**(PM 式排序)——归**有用**。**agent 决定强调,外壳保证无遗漏。** 别把"看哪些 / 不饿死"交给 agent——那是把安全属性塞进不被信任的一方(违 §2)。

## 十二、有用靠充实方法论,不靠加机制
每个 agent 是一个**有方法论的角色**(maintainer=项目经理、patcher=研发、reviewer=架构/QA)。要它更强,**改它的 persona / 方法论,别建新 judge / 机制**。"有用随模型涨"= persona 里的方法论越用越好,**外壳不增厚**(§8/§9 的当然推论)。

---

## 修订准则

新增任何机制前,先问两句:

1. **它服务"安全"还是"有用"?** ——有用的,优先塌进 agent,别建外壳机制。
2. **它是不是更强模型会吃掉的脚手架?** ——是,就别建,或建得能随手弃。

凡与本宪法冲突的设计,改设计,不改宪法——除非先修宪法。
